📝 หน้า 1 — บันทึกข้อความ (ข้อมูลโครงการ สัญญา และคณะกรรมการ)
================================================================================
1. DOC_NO
   - เลขที่บันทึกข้อความ (เว้นว่างไว้เสมอ)

2. R_DATE  (alias ของ REPORT_DATE)
   - วันที่รายงาน = วันจันทร์ของสัปดาห์ถัดไป อ้างอิงจาก END_DATE ของสัปดาห์นั้น

3. WEEK  (alias ของ WEEK_NO)
   - รายงานครั้งที่ / สัปดาห์ที่ เริ่มจาก 1 รันตามลำดับจนสิ้นสุดสัญญา

4. START  (alias ของ START_DATE)
   - ตั้งแต่วันที่ (สัปดาห์ที่ 1 อิงจากวันที่ผู้รับจ้างเริ่มทำงาน)

5. END  (alias ของ END_DATE)
   - ถึงวันที่ (วันสิ้นสุดของสัปดาห์นั้นๆ)

6. PROJECT  (alias ของ PROJECT_NAME)
   - ชื่อโครงการ (ดึงจากสัญญาจ้าง)

7. LOCATION
   - สถานที่ก่อสร้าง (ดึงจากสัญญาจ้าง)

8. QTY  (alias ของ QUANTITY)
   - ปริมาณงาน (ต่อท้ายสถานที่ก่อสร้างในสัญญา ตัดก่อนคำว่า "รายละเอียดแบบแปลน...")

9. C_NO, C_DATE, C_END, DAYS
   - เลขที่สัญญา / วันลงนาม / วันแล้วเสร็จ / จำนวนวันรวมตามสัญญา

10. COST  (alias ของ CONSTRUCTION_COST)
    - ค่าก่อสร้าง/ค่าจ้าง จากข้อ "ค่าจ้างและการจ่ายเงิน" ในสัญญา

11. FINE  (alias ของ FINE_PER_DAY)
    - ค่าปรับรายวันตามสัญญา

12. CONTRACTOR  (alias ของ CONTRACTOR_NAME)
    - ชื่อผู้รับจ้าง

13. REMAIN
    - ระยะเวลาก่อสร้างคงเหลือ = DAYS - จำนวนวันที่ทำไปแล้วจนถึงงวดนี้

14. BUDGET
    - งบประมาณ/เบิกจ่าย — ใช้ซ้ำ 2 จุดในตาราง (แถวปีงบประมาณ + แถวรวม) ตั้งใจให้เท่ากัน ไม่ใช่บั๊ก

15. SUP_NAME, SUP_POS
    - ชื่อ-ตำแหน่งผู้ควบคุมงาน (ใช้ในเนื้อหาหน้า 1)

16. COM_P_NAME, COM_P_POS
    - ชื่อ-ตำแหน่งประธานกรรมการตรวจรับพัสดุ

17. COM_1_NAME, COM_1_POS, COM_2_NAME, COM_2_POS
    - ชื่อ-ตำแหน่งกรรมการตรวจรับพัสดุ คนที่ 1 และ 2

📝 หน้า 2 — ผลการดำเนินงานในสัปดาห์ (ตารางแถวเดียว ไม่ใช่ loop)
================================================================================
โครงสร้างจริงในไฟล์: 4 แถว (หัวตาราง 2 แถว + ข้อมูล 1 แถว + รวม 1 แถว)
ไม่มี loop tag ในตารางนี้ — ต่างจากตารางแรงงานที่จำนวนแถวไม่คงที่ ตารางนี้คือภาพรวมทั้งสัญญาต่อ 1 สัปดาห์ จึงมีแค่ 1 แถวข้อมูลเสมอ

แถวข้อมูล:
1. WN
   - เลขสัปดาห์ = ค่าเดียวกับ WEEK_NO (ใส่ในคอลัมน์ "ที่")

2. WD
   - งานที่ดำเนินการ — ไม่ใช่ให้พิมพ์เอง เป็นค่าที่ระบบต่อให้อัตโนมัติ
   - วิธีคำนวณ (ฝั่ง JS): นำ DAY_DESC_1..DAY_DESC_7 (ที่กรอกในตารางรายวันหน้า 3) มาต่อเป็น bullet list
     บรรทัดละ 1 วัน คั่นด้วย \n เรียงตามลำดับวันจริงในสัปดาห์ ข้ามช่องที่ไม่มีวันที่
   - ต้องอาศัย docxtemplater option "linebreaks: true" (มีอยู่แล้วในโค้ดปัจจุบัน) เพื่อให้ \n ขึ้นบรรทัดใหม่ในเซลล์เดียวกันได้จริง

3. WW
   - สัดส่วนของงาน% — ผู้ใช้กรอกเองทุกสัปดาห์ผ่านแอป (ไม่ fix 100%)

4. WP
   - ถึงสัปดาห์ก่อน% — auto carry-forward จากค่า WC (สะสม) ของสัปดาห์ก่อนหน้า

5. WT
   - ในสัปดาห์นี้% — ผู้ใช้กรอกเองผ่านแอป

6. WC
   - สะสม% — auto คำนวณ = WP + WT

7. WR
   - ผลงานรวม% — ผู้ใช้กรอกเองผ่านแอป ไม่ auto-calculate

แถว "รวม" (ท้ายตาราง):
   - ช่อง "สัดส่วนของงาน%" และ "ผลงานรวม%" → ใช้ tag เดิมซ้ำ (WW, WR) เพื่อ mirror ค่าจากแถวข้อมูล
   - ช่อง "ถึงสัปดาห์ก่อน / ในสัปดาห์นี้ / สะสม" (merge เป็นช่องเดียว) → ข้อความ "รวม" ธรรมดา ไม่มีตัวแปร

ปัญหา-อุปสรรค:
   - ไม่มีตัวแปรใดๆ ทั้งสิ้น ปล่อย checkbox และเส้นว่างไว้ตามต้นฉบับ
   - ไม่มีช่องกรอกในหน้าแอปเลย — ผู้ใช้ปริ้น/ดาวน์โหลดไฟล์แล้วไปกรอกมือทีหลังนอกระบบ

📝 หน้า 3 — บันทึกการปฏิบัติงานของผู้รับจ้าง (ตารางรายวัน + ตารางแรงงาน)
================================================================================

## ตารางรายวัน (7 แถวคงที่ — Date_1..7 เท่าเดิม)
1. D1 ถึง D7  (alias ของ Date_1..Date_7)
   - วันที่แบบเต็ม เรียงลำดับวันที่ 1-7 ของสัปดาห์ ว่างไว้ถ้ายังไม่ถึงวันเริ่มงาน

2. DAY_DESC_1 ถึง DAY_DESC_7
   - รายละเอียดการดำเนินงานต่อวัน "ผู้ใช้พิมพ์เอง" ผ่านแอป (Step 4)
   - ถ้าไม่ได้กรอก ให้ default เป็น "ไม่ปฏิบัติงาน"
   - จับคู่ index เดียวกับ D1..D7 เสมอ
   - ข้อมูลชุดนี้คือต้นทางของ WD ในหน้า 2 (sync จุดเดียว ไม่พิมพ์ซ้ำสองที่)

3. W_A1 ถึง W_A7 (เช้า) / W_P1 ถึง W_P7 (บ่าย)
   - สภาพอากาศ ถ้าไม่มีข้อมูลให้ default เป็น "แจ่มใส"

## ตารางแรงงาน (loop — จำนวนแถวไม่คงที่)
1. SD1 ถึง SD7  (หัวตาราง)
   - วันที่ย่อติดปี พ.ศ. 2 หลัก เริ่มจากวันที่ผู้รับจ้างเริ่มงานจนสิ้นสุดสัปดาห์ ช่องที่เหลือเว้นว่าง

2. {#laborRows} ... {/laborRows}  (loop table, docxtemplater)
   - เปิด tag ที่ต้นเซลล์แรกสุดของแถว (เซลล์ชื่อประเภทแรงงาน)
   - ปิด tag ที่ท้ายเซลล์สุดท้ายของแถวเดียวกัน (เซลล์ d7)
   - ตัวแปรภายใน loop ต่อแถว:
     - category : ชื่อประเภทแรงงาน (ผู้ใช้พิมพ์เอง เพิ่ม/ลบแถวได้ผ่านแอป)
     - d1 ถึง d7 : จำนวนคนต่อวัน จับคู่ index กับ SD1..SD7

3. LABOR_TOTAL_1 ถึง LABOR_TOTAL_7  (แถว "รวม" นอก loop)
   - ผลรวมจำนวนแรงงานต่อวัน คำนวณจาก sum ของทุกแถวใน laborRows

## ลายเซ็นท้ายหน้า 3
   - SUPERVISOR_NAME = ผู้ควบคุมงาน (ค่าเดียวกับ SUP_NAME หน้า 1 คนละ alias)
   - CONTRACTOR_NAME = ผู้รับจ้าง (ค่าเดียวกับ CONTRACTOR หน้า 1 คนละ alias)
   - ไม่ต้องกรอกซ้ำ ดึงจากข้อมูลโครงการที่กรอกครั้งเดียวในแอป

================================================================================
🔄 สรุปฟังก์ชัน SYNC (state.weeks[idx] คือ single source of truth)
================================================================================
โครงสร้างข้อมูลที่ต้องมีใน state.weeks[idx]:

    w.dailyNarrative = ["", "", "", "", "", "", ""];   // → DAY_DESC_1..7 และต้นทางของ WD
    w.laborRows = [
      { id: "l1", category: "", counts: [0,0,0,0,0,0,0] }
    ];                                                   // → {#laborRows} loop + LABOR_TOTAL_n
    w.workProgress = {
      weight: 0,        // → WW (ผู้ใช้กรอก)
      prevPercent: 0,    // → WP (auto carry จากสัปดาห์ก่อน .cumulative)
      thisWeek: 0,       // → WT (ผู้ใช้กรอก)
      cumulative: 0,     // → WC = prevPercent + thisWeek (auto)
      rowTotal: 0        // → WR (ผู้ใช้กรอก ไม่ auto-calc)
    };
    // ไม่มี w.problems อีกต่อไป — ปัญหา-อุปสรรคไม่ sync กับแอป

ลำดับการคำนวณเมื่อเปลี่ยนสัปดาห์ (selectWeek / computeAllWeeks):
    ถ้า idx > 0:
      state.weeks[idx].workProgress.prevPercent = state.weeks[idx-1].workProgress.cumulative

จุดที่ข้อมูลต้อง sync ไปพร้อมกัน 2 ทาง เสมอ (ห้ามคำนวณซ้ำสองที่ ให้คำนวณครั้งเดียวใน buildWeekDisplayModel(w)):
    1) หน้า Step 5 "ตัวอย่าง" ในแอป (ก่อน export)
    2) เอกสาร .docx ที่ export จริง (ผ่าน collectAllData())

- PROJECT          <---> PROJECT_NAME

- C_NO / CONTRACT_NO       <---> C_NO
- C_DATE / CONTRACT_DATE   <---> C_DATE
- C_END / CONTRACT_END_DATE <---> C_END
- DAYS / TOTAL_DAYS        <---> DAYS
- COST             <---> CONSTRUCTION_COST
- FINE             <---> FINE_PER_DAY
- CONTRACTOR       <---> CONTRACTOR_NAME
- REMAIN / REMAIN_DAYS     <---> REMAIN
- BUDGET / TOTAL_BUDGET    <---> BUDGET
- WEEK             <---> WEEK_NO
- START            <---> START_DATE
- END              <---> END_DATE
- R_DATE           <---> REPORT_DATE
- SUP_NAME         <---> SUPERVISOR_NAME
- SUP_POS          <---> SUPERVISOR_POSITION
- COM_P_NAME       <---> COMMITTEE_PRESIDENT_NAME
- COM_P_POS        <---> COMMITTEE_PRESIDENT_POSITION
- COM_1_NAME       <---> COMMITTEE_1_NAME
- COM_1_POS        <---> COMMITTEE_1_POSITION
- COM_2_NAME       <---> COMMITTEE_2_NAME
- COM_2_POS        <---> COMMITTEE_2_POSITION
- SD1..SD7         <---> ShortDate_1..ShortDate_7
- D1..D7           <---> Date_1..Date_7

📝 ตัวแปร V2 ใหม่ (ไม่มี alias ยาว — ตั้งใจให้สั้นตั้งแต่แรก):
- DAY_DESC_1..DAY_DESC_7   : รายละเอียดรายวัน (ผู้ใช้กรอกในแอป)
- WN   : เลขสัปดาห์ (alias ของ WEEK_NO)
- WD   : งานที่ดำเนินการ (auto-รวมจาก DAY_DESC_1..7)
- WW   : สัดส่วนของงาน% (ผู้ใช้กรอก)
- WP   : ถึงสัปดาห์ก่อน% (auto carry-forward)
- WT   : ในสัปดาห์นี้% (ผู้ใช้กรอก)
- WC   : สะสม% (auto = WP + WT)
- WR   : ผลงานรวม% (ผู้ใช้กรอก)
- LABOR_TOTAL_1..LABOR_TOTAL_7 : ผลรวมแรงงานต่อวัน (auto sum)

  - "สถานะ เร็ว/ช้า" ที่เคยเสนอคู่กัน — ตัดออก ไม่ทำ
